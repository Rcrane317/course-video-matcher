# B站 检索与判定手册

## 一、先理解 B站 的三种「一门课」

| 形态 | 长什么样 | 怎么用 |
|---|---|---|
| **分P视频** | 一个 BV 号下挂几十个 P，`?p=N` 切集 | 最常见。合集判定看分P数；定位靠 `?p=N` |
| **合集（ugc_season）** | 同一 UP 主把多个 BV 收进一个合集，页面显示「合集·共 N 集」 | 需要逐个 BV 取链接，`episodes` 填合集总数 |
| **单集片段** | 一个 BV 只有 1 P，讲一个知识点 | `kind: "snippet"`，只用来补缺口 |

同一个 UP 主常常把多门课塞进一个投稿，所以**只给 BV 不给 P 等于给错链接**。

## 二、检索式

用工具的域名限定（`allowed_domains: ["bilibili.com"]`），比在关键词里写 `site:` 稳。

| 目的 | 检索式 | 说明 |
|---|---|---|
| 找正课合集 | `{课程名} 完整版`、`{课程名} 全集`、`{课程名} 合集` | 命中率最高的一组 |
| 锁定同源课 | `{课程名} {学校}`、`{课程名} {教师}` | 课件若是某校课堂录播，这组最准 |
| 找教材配套 | `{教材名} 配套 讲解` | 严蔚敏、汤小丹、唐朔飞这类教材名很有效 |
| 补单点 | `{课程名} {知识点} 讲解` | 只在 Stage B 用 |
| 英文课 | `{course} lecture {n} bilibili` | 搬运的国外公开课 |

关键词 2–4 个概念最佳，堆到 6 个以上基本返回空。

**常见正课来源的先验**（可作检索起点，但每一条都必须核实，不能凭印象填）：
高校官方号 / 教务处号、计算机类培训机构的正课系列、知名教师课堂录播。搜「{课程名} 课堂录播」往往比搜「{课程名} 教程」更接近课件。

## 三、判定「是不是完整合集」

按顺序看，前两条满足即可标 `kind: "collection"`：

1. 分P数 ≥ 5，或页面显示「合集·共 N 集」。
2. 标题含 `全集 / 完整版 / 合集 / 系列 / 课堂录播 / 公开课 / 第X讲`。
3. 分P标题呈章节结构（第1章…第N章 / 1.1、1.2…），而不是「1、2、3」。
4. 分P数与该课程大纲的章数大致相当（差 30% 以内算合理）。

只有一个 BV 单集、或专门讲一个知识点的，记 `snippet`。

## 四、判定「免费」

| 页面信号 | 结论 |
|---|---|
| 全部分P可直接播放，无「试看」角标 | `free: true` |
| 前几 P 能看、后面标「试看结束」「购买后观看」 | `free: false` → 丢弃 |
| 标题/简介写「付费课程」「充电专属」「课程购买」 | `free: false` → 丢弃 |
| 简介写「完整版在简介/评论区/私信获取」「加群领资料」 | **按广告处理，直接丢弃** |
| 需要登录但登录后免费 | `free: true`，备注「需登录」 |

## 五、判定「已更新完毕」

| 信号 | 结论 |
|---|---|
| 最后一集能播，标题/简介无更新说明 | `complete` |
| 标题或简介含「持续更新」「更新中」「每周更新」「未完待续」 | `updating` → 丢弃 |
| 最后一 P 是「预告」「下次讲」 | `updating` → 丢弃 |
| 判断不了（页面打不开、信息不足） | `unknown` → 保留但会标「完结未确认」，不给高置信 |

发布时间是个辅助信号：一门 40 讲的课，最后一集发布距今已半年以上且无更新说明，基本可判 `complete`。

## 六、判定「此刻还能不能看」

搜索摘要永远不会告诉你视频已经下架。`scripts/probe.py` 逐条请求
`https://api.bilibili.com/x/web-interface/view?bvid=<BV>`（公开接口，不登录、不下载），
一次拿到四类信息：

| 接口返回 | 判定 | 说明 |
|---|---|---|
| `code: 0` | 在播 | 再看 `pages`、`rights`、`is_upower_exclusive` 做细分 |
| `code: -404`，`message: 啥都木有` | 已删除 | 稿件不存在，最常见的一种 |
| `code: 62002` | 不可见 | 已删除或设为私密 |
| `code: 62004` / `62005` | 审核中 / 被屏蔽 | 当下看不了，按不可用处理 |
| `code: -403` | 无权限 | 可能是年龄限制或区域限制 |
| `code: -412` / `-352` | 触发风控 | **不是**视频的问题，重试即可，别据此删条目 |

稿子在播，还要再查三件事：

1. **分P存在性**：`pages[]` 里有没有 `page == N`。没有就是链接指错了集（`part_missing`）。
2. **是否真免费**：`rights.pay` / `rights.arc_pay` / `rights.ugc_pay` / `is_chargeable_season`
   任一为真 → 付费；`is_upower_exclusive` / `is_upower_preview` 为真 → 充电专属，也算看不了。
3. **链接真伪**：把接口返回的 `title` + `pages[N].part` 与 candidates 里声明的标题做比对。
   完全对不上（相似度 < 0.10）说明这个 BV 是凭印象编的，直接剔除（`mismatch`）。

**判断「已完结」也可以用接口**：`pubdate` 是很久以前、`pages` 数与你已知的大纲相当、
标题里没有「更新中」，基本可判 `complete`。但接口不返回「是否还在更新」，仍要结合标题与简介。

**节流**：默认每条间隔 0.4s、并发 4；一门 60 讲的课大约 15 秒。
连续返回 `-412` 就停手，隔几分钟再来——硬刚只会让风控更久。

## 七、广告/卖课特征

词表命中即丢（脚本内置）：`扫码 / 私信 / 加微信 / 加V / vx / 微信 / QQ群 / 领取 / 获取 / 资料包 / 网盘 / 提取码 / 报名 / 咨询 / 一对一 / 1对1 / 保过 / 包过 / 押题 / 内部资料 / 辅导班 / 培训班 / 滴滴我 / 评论区 / 简介 / 购买 / 拼课 / 代看 / 代刷`

**词表抓不到的，靠语义判**，这些也按广告丢：

- 标题党：「3 小时救命」「考前必看 30 分钟」「押中 90%」
- 体量对不上：一门 60 讲的课，号称「一集讲完」——真要收录也只能当片段，不能当合集
- 内容空心：封面大字 + 全片讲「怎么复习」而不是讲知识
- UP 主是机构号但只发试听片段，正片引到私域

判断原则：**这门课是给人学知识的，还是给人加微信的**。前者留，后者丢。

## 八、搜索被污染时的替代路径

1. **换主体词**：把「教程/速成/考研」换成「课堂录播/公开课/本科课程」，卖课池会明显减少。
2. **换人称**：搜「{教师名} {课程名}」比搜课程名更干净，教师名不太会被 SEO 污染。
3. **换地点**：搜「{学校} {课程名}」，高校官方号内容通常不投广告词。
4. **从已知好系列反查**：先确认一个可信合集，再看同 UP 主是否还有同课程的其他分P。
5. 如果 8 次检索后仍全是卖课，就如实报告「该课程在 B站 的免费正课资源稀缺」，并给替代方案（换课程名、看教材配套、同类课替代），**不要为了凑覆盖率把卖课视频放进来**。

## 九、链接规范

- 统一用 `https://www.bilibili.com/video/BVxxxxxxxxxx?p=N`。
- 把 `b23.tv` 短链、`m.bilibili.com` 移动链还原成上面的形式，方便用户判断。
- 收藏夹/合集页链接（`/list/`、`/medialist/`）不是视频页，不能当播放地址；合集要么给第一集的 BV，要么逐集给 BV。
- 旧版 `av` 号尽量换成 BV 号。

## 十、效率约束

- 单门课 ≤ 8 次检索；合集定了就靠分P标题定位。
- 每个系列只打开 1 次播放列表页。
- 批量处理时先跑通 1 门课再铺开，避免在错的检索式上浪费一轮。
