# 打分、排序与裁决

分数只有一个含义：**这条链接值不值得点开**。不是学术评分，不要为了让表好看抬分。

## 一、自动分（align.py）

```
auto = 0.60 × 字面相似度 + 0.25 × 关键词覆盖率 + 调整项
```

| 分量 | 算法 | 抓的是什么 |
|---|---|---|
| 字面相似度 | 讲义标题 vs「系列名 + 分P标题 + UP主」的中文二元组 Jaccard | 名字都对不上，基本不是同一个东西 |
| 关键词覆盖率 | `topics` 有多少比例出现在候选文本里 | 「栈 / KMP / PCB」这类硬信号 |
| 调整项 | 官方/高校/机构号 +0.06；时长 4–180 分钟 +0.02；已开页面核实 +0.04；时长离谱 −0.05 | 修正纯字面误判 |

有 `llm_score` 时以它为准，`auto_score` 留作对照。两者差 > 35 会在 JSON 里标 `disagreement`——**这些条目要回头复核**，通常是你给分虚高，或标题误导了你。

## 二、llm_score 锚点

| 分数 | 含义 | 典型情形 |
|---|---|---|
| 95–100 | 同一门课同一讲 | 教师、学校、教材、章节顺序全对上 |
| 80–94 | 主题一致，可替代 | 别校同名课，范围重合、深度相当 |
| 65–79 | 相关但需调整 | 顺序不同、有删减、合集里夹了习题课 |
| 45–64 | 只部分重合 | 只覆盖本章某一节；或考研速成 |
| < 45 | 不要用 | 只是名字里出现了同一个词 |

判断顺序：**是不是同一门课（教材+教师+学校）→ 是不是同一章（主题词）→ 体量是否相当（时长/集数）**。

## 三、五道门禁先于分数

分数再高，过不了门禁也不收录（由 `align.py` 执行）：

1. **平台**：必须是 `bilibili.com` / `b23.tv`，否则 `filters.other_platform` +1。
2. **广告**：标题/UP主命中强词或弱词、简介命中强词 → `filters.ad` +1，整条丢弃；
   简介只命中弱词（网盘/资料包/提取码）→ 保留，打「可能是课件网盘」提示。
3. **付费**：`free === false`，`filters.paid` +1。
4. **未完结**：`status === "updating"`，`filters.updating` +1。
5. **存活**（`probe.py` 的结果）：`dead` / `part_missing` / 实际 `paid` / `restricted` /
   `mismatch` 一律丢弃，分别计入 `filters.dead`（前三类合并）、`filters.paid`、`filters.mismatch`；
   `blocked` 默认丢（`filters.unverified`），加 `--allow-unverified` 才保留并标「在播未核验」。

**第 5 道是唯一会随时间变化的门禁**——今天通过，明天视频可能就没了。所以报告里必须写核验时间，
HTML 里每条候选也带 `✓ 已核实在播 · MM-DD HH:MM`。

`free === null` 或 `status === "unknown"` 的放行，但会带一个黄色提示标签（「免费未确认」「完结未确认」），并且不能作为高置信推荐。

## 三·五、模式调整（标题定死，体量兜底）

语义分回答「是不是这门课的这一讲」，模式分回答「是不是你要的形态」。两者相加才是最终分。

```
final = clamp(语义分 + mode_points, 0, 100)
```

`mode_points` 只有两档，**标题的权重远高于时长**：

| 情形 | 判定 | 加减分 |
|---|---|---|
| 标题含突击类词（`突击/速成/期末/考前/冲刺/串讲/考点/复习/救命/速通/浓缩/划重点/总结/N小时`），且不含全程类词 | 整条归**突击** | 突击模式 +24；全程模式 −24 |
| 标题含全程类词（`完整版/全集/全程/系统/课堂/录播/详解/逐章/配套教材/零基础`），且不含突击类词 | 整条归**全程** | 全程模式 +24；突击模式 −24 |
| 两类都没有，或两类都有 | 看体量 | 全程倾向 = `bigness`，突击倾向 = `1 − bigness`，换算成 ±10 分 |

`bigness`（0..1）由时长和集数合成，时长占 6.5 成：

| 整门时长 | 分值 | 集数 | 分值 |
|---|---|---|---|
| ≥15h / ≥10h / ≥6h / ≥3h / 更短 | 1.0 / 0.8 / 0.6 / 0.35 / 0.15 | ≥20 / ≥10 / ≥5 / 更少 | 1.0 / 0.8 / 0.5 / 0.2 |

**为什么关键词给 ±24 而不是 ±15？** 因为要能压过语义分的自然差距。一门 40 小时的「期末突击」在全程模式下语义分可能有 80，只有扣够 24 分才会掉到真正的系统课之后。反之，2 小时的「完整版」在全程模式下也该赢过同分的速成课。

**为什么标题优先于时长？** 时长会被「合集型账号把多门课塞进一个投稿」污染，也会被「一门课拆成 40 个短 P」放大；标题是作者自己写的形态声明，比体量可靠得多。

**只看标题，不看简介。** 简介里「配套期末复习资料」这类句子会把系统课误判成突击课。

**模式不改变门禁。** B站、免费、完结、无广告、未删除，五条在两种模式下一样严；只有排序会变。

## 四、分级

| 最终分 | 等级 | HTML 里的表现 |
|---|---|---|
| ≥ 75 | 高置信 | 绿色分数块，可直接点开 |
| 55–74 | 待核验 | 琥珀色，标「仅搜索摘要」等缺口 |
| 35–54 | 弱匹配 | 灰色，只当补充 |
| < 35 | 不收录 | 计入 `filters.low_score`，不进表 |

**一讲列几条？** 全部。按分数从高到低排，最多保留 10 条（再多对用户没意义）。不做「只给 top1」的截断——同一个知识点不同老师讲法不同，用户可能需要试听。

## 五、合集优先怎么落地

这是本技能最容易被误用的地方，规则写死：

1. 一讲有合格合集（tier ≠ weak）→ 该讲状态记 **`collection`（含完整合集）**，即使某条片段的分数更高。理由是跟一个系列看，顺序和深度最接近整门课。
2. 没有合格合集、但有合格片段 → 记 **`snippet`（仅专题片段）**，HTML 里明确标「片段」，提示用户这只是补点。
3. 只有弱匹配 → 记 **`weak`（仅弱匹配）**，不算覆盖。
4. 什么都没有 → **`not_found`**，进缺失清单。

注意：**排序仍按分数**，所以「含完整合集」的那一讲，排第一的可能是条片段。这是刻意的——用户要能看到所有选择，标签负责说明性质。覆盖率只统计 `collection + snippet`，弱匹配不算。

## 六、覆盖率红线

```
覆盖率 =（含完整合集 + 仅片段）/ 有效讲义数      # 有效 = 去掉重复文件
```

- ≥ 70%：正常交付，说明主流章节都有对应。
- 50–69%：交付，但报告里要写清缺口集中在哪几章。
- < 50%：**先别交付**。按顺序排查：课程身份是否认错（最常见）→ `topics` 是否太泛 → 检索词是否太窄/撞进卖课池。改完重跑；仍然低就如实说「B站 免费正课资源覆盖不全」，并给替代方案。

## 七、不要做的事

- 不要为了刷覆盖率，把「同名不同课」的链接打 60 分。
- 不要手工把速成课的 `llm_score` 打到 90 再指望模式扣分把它压下去——语义分只衡量「是不是这门课」，形态交给 `--mode`。
- 不要为了凑数，把 `updating` 的系列标成 `complete`。
- 不要在没有 `evidence=page` 的情况下写具体分P号或时间戳。
- 不要把同一系列所有讲都填同一个 `llm_score`；综述章容易对，习题章难对，分差是真实的。
- 不要在报告里说「已找到全部」，只能说「找到 N 条符合条件的，另有 M 讲缺失」。
